# Спецификация библиотеки сохранения черновиков

Дата: 2026-10-22. Основание: полное техническое задание пользователя из приложенного файла.

## Результат и границы

Самостоятельный TypeScript npm-пакет `@your-scope/react-hook-form-persist`, версия 0.1.0, в текущем отдельном Git-репозитории. Имя временное; реальный scope, автор и URL репозитория не выдумываются. Публикация, создание удалённого репозитория и отправка кода не входят в разрешённые действия.

React 18/19 и совместимые React Hook Form 7 — peer dependencies. Никаких зависимостей от Next.js, монорепозитория или внутренних пакетов. README на русском, краткая документация на английском. Исходное ТЗ сохраняет силу; эта спецификация уточняет решения, а не сокращает требования.

## Архитектура и альтернативы

Выбран единый core с внедряемым адаптером, общим контекстом и тонкими entrypoint. Независимые реализации хуков увеличили бы риск расхождения поведения. Единый entrypoint с обязательным параметром хранилища нарушил бы запрошенный API и затруднил бы исключение IndexedDB из local bundle.

- `core/types.ts`: публичные контракты FormDraft, PersistAdapter, параметры и результат хука.
- `core/context.tsx`: вложенный PersistFormProvider; используется ближайший Provider.
- `core/create-persist-hook.ts`: выбор стратегии без копирования алгоритма.
- `core/use-persist-form.ts`: React-жизненный цикл, подписка и публичные методы.
- Отдельные внутренние модули: проверка envelope, исключение путей, очередь операций.
- `adapters/web-storage.ts`: одна реализация для localStorage/sessionStorage.
- `adapters/indexed-db.ts`: idb, ленивое соединение с повторным использованием.

Основной импорт выбирает Provider, иначе IndexedDB. `/local`, `/session`, `/indexed` всегда выбирают своё хранилище. `/custom` требует Provider и выдаёт понятную ошибку без него. Контекст общий для всех entrypoint; специализированные импорты не учитывают его адаптер.

## Контракт и типизация

Сохраняются заданные интерфейсы: FormDraft<T> содержит version, updatedAt, values; PersistAdapter содержит асинхронные get<T>, set<T>, remove. Адаптеры не импортируют React или RHF. Типизация хука учитывает FieldValues, FieldPath и параметры UseFormReturn, включая преобразованные resolver значения. Сохраняются входные значения формы, а не результат resolver.

Значения по умолчанию: debounce 500 мс, maxAge 30 дней, version 1, enabled true. Некорректные числовые настройки отклоняются явно. Ошибки доступны через status; публичные flush/clearDraft отклоняют Promise при неуспехе, фоновые ошибки перехватываются.

Runtime проверяет envelope, конечные числовые version/updatedAt и объект values. Полную предметную схему нельзя вывести из TypeScript: восстановленные данные остаются недоверенными, приложение проверяет их resolver/своей схемой перед отправкой. Повреждённые, просроченные и несовместимые черновики не восстанавливаются и удаляются; ошибка удаления отражается в status.

## Жизненный цикл и конкурентность

Каждая комбинация adapter/key/enabled образует поколение сессии. Результат устаревшей сессии не сбрасывает новую форму и не обновляет её состояние. Очередь на пару adapter/key сериализует операции внутри одного экземпляра библиотеки, включая перекрывающиеся монтирования. Отдельные вкладки и разные экземпляры адаптера не имеют общей блокировки.

Порядок: чтение → проверка → reset → подписка → ready. До завершения восстановления начальные значения не сохраняются. Для медленного чтения изменения, уже внесённые пользователем, не должны молча теряться: при изменившихся относительно начала чтения значениях восстановление пропускается. Это поведение проверяется отдельно.

Подписка использует публичный form.subscribe; минимальная поддерживаемая версия RHF определяется по реальному наличию и сигнатурам этого API и фиксируется в peerDependencies. Callback подписки только снимает значения и планирует сохранение, не вызывает reset/setValue. Снимок отделяется от изменяемых объектов формы до асинхронной записи.

Debounce объединяет изменения. Записи выполняются последовательно. lastSavedAt обновляется только после подтверждённой записи; hasDraft отражает подтверждённое наличие. isRestored означает завершение попытки чтения, в том числе с ошибкой, и не сбрасывается из-за saving.

flush отменяет debounce, ставит текущий ожидающий снимок в очередь и ждёт записи; если изменений нет, ждёт уже выполняющиеся операции. До восстановления не записывает начальные значения. clearDraft отменяет ожидающее сохранение и ставит удаление после начатых записей; поздние результаты чтения не восстанавливают удалённый черновик. Изменения после вызова очистки могут создать новый черновик.

При смене ключа/адаптера и unmount отменяются таймеры и подписки; не начатые записи отбрасываются. Начатую операцию произвольного адаптера отменить невозможно. Для гарантии сохранения перед навигацией пользователь вызывает await flush(). Strict Mode не создаёт лишнюю запись и не допускает reset от отменённого эффекта.

enabled false не читает и не сохраняет, не удаляет существующий черновик. isRestored false, status ready до включения. Для асинхронных defaultValues документируется enabled: !form.formState.isLoading. Стабильный объект adapter обязателен: Provider не пересоздаёт его, примеры используют модульную константу/useMemo. Настоящая смена ссылки означает смену адаптера.

## Исключения и безопасность

exclude поддерживает вложенные пути и индексы массивов; фильтрация применяется при чтении и записи без изменения исходных объектов. Исключённые значения при восстановлении сохраняют текущие/default значения формы. Опасные пути prototype/constructor/__proto__ не используются для изменения прототипов.

По умолчанию рекурсивно исключаются распространённые имена чувствительных полей: password, confirmPassword, token, accessToken, refreshToken, secret (без учёта регистра). Добавляется явно документированная опция persistSensitiveFields: true для сознательного отключения этой защиты; пользовательский exclude сохраняет приоритет. Автоматическое распознавание не гарантирует обнаружение всех секретов, приложение обязано исключать собственные чувствительные поля.

Web Storage имеет JSON-ограничения; циклы и BigInt приводят к обработанной ошибке. IndexedDB использует structured clone без JSON и поддерживает соответствующие типы; функции и другие неклонируемые значения вызывают обработанную ошибку. Browser API не используются при импорте/SSR.

Несколько вкладок: последняя завершившаяся запись побеждает, без слияния и live-синхронизации. TTL не гарантирует сохранность данных при очистке браузером. Browser storage не защищён от XSS. Custom API обязан проверять авторизацию и принадлежность ключа на сервере.

## Сборка, примеры и релизы

ESM, декларации, sourcemaps, tree-shaking, пять exports с реальными путями. React/RHF/idb внешние зависимости; local/session bundle не содержит idb. Клиентские entrypoint сохраняют use client. Общий context не дублируется между entrypoint. CommonJS в первой версии не требуется.

Сборщик tsdown; строгий TypeScript, ESLint, Vitest, Testing Library, fake-indexeddb. Выбор совместимых актуальных версий сверяется с официальной документацией и проверяется сборкой.

Минимальные независимые примеры Vite и Next.js (App Router и пояснение Pages Router), Controller, useFieldArray, Zod и очистка после успешной отправки. Примеры и тесты исключены из npm tarball allowlist через files.

CI: install из lockfile, typecheck, lint, test, build, проверка пакета. Матрица React 18/19. Релиз — отдельный вручную запускаемый workflow с проверкой SemVer/tag, CHANGELOG, GitHub Release и npm Trusted Publishing/OIDC/provenance. До настоящей публикации требуется выбрать настоящее npm-имя и настроить доверенного издателя; workflow блокирует временный scope. Никаких npm publish при выполнении задания.

## Проверка готовности

Дополнительно: редактирование во время медленного чтения, очистка во время чтения и записи, несколько перекрывающихся сессий, resolver-типы, опасные пути, structured clone и отсутствие browser API при SSR. Тесты типов проверяют публичные exports и отклонение неверных FieldPath.
